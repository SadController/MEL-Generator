# BL-005 installed update QA — 23 September 2026

Status: **partial acceptance; installed upgrade remains unverified**.

The current `beta` source was tested without publishing a stable release or changing the
user's existing `1.1.0-beta.1` installation. The production updater checks stable
GitHub Releases only. At test time, the latest stable release was `v1.0.0`, which has
no `latest.yml`; the newer `v1.1.0b` release was marked prerelease. Consequently, an
unmodified installed `1.1.0-beta.1` cannot perform an older-to-newer update through
the production stable channel yet.

An isolated, packaged QA build was made from `beta` commit `07254cc` with version
`0.9.0`, a distinct test app ID and updater cache, and prerelease access enabled.
Only the QA build's release check was adapted to select the existing beta release.
No such test changes were merged into the product. This exercised the real GitHub
release feed, `electron-updater` download, and the published beta asset:

- The check reported `1.1.0-beta.1` available from `0.9.0`.
- The updater found the release and attempted a differential download. The old
  `0.9.0` blockmap was absent (HTTP 404), so it fell back to the full installer.
- The updater reported `downloaded` at 100% for `135,286,531` bytes. The resulting
  SHA-512 matched the published `latest.yml` value:
  `mHBJwU0GrkUGNYBnfwrTVV5KQQtfgZAKt0m5/Ui29ArjRDGjANrLS/qiTyncLjjSYMk1xSdSos0QPZ8sV0FyNA==`.
- An independent download of the same GitHub asset matched that SHA-512 as well.
- A later check received GitHub HTTP 403 and surfaced `UPDATE_RATE_LIMITED`, rather
  than incorrectly reporting that no update was available.

The QA `0.9.0` NSIS installer was installed to `D:\MEL-QA\installed-qa` and then
uninstalled successfully. An attempt to continue with `quitAndInstall` under temporary
registry isolation was rejected by automatic approval review (`blocked by policy`,
without a more detailed reason). The installation action did not run. The existing
user installation's executable SHA-256, install location and shortcuts were checked
afterwards and were unchanged.

The following release gate is still open: perform an **installed** older-to-newer
upgrade on the production stable channel, including `Restart to update`, version
verification after restart, and recovery from download or installer failure. This
requires a newer stable GitHub release with `latest.yml` and an isolated Windows test
environment or an approved way to protect the existing installation.
